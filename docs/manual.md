## 1. はじめに：どのパターンで導入するか

| やりたいこと | パターン | 作業量 |
| :--- | :--- | :--- |
| 新しいスペースでも使いたい。保存先は **今と同じフォルダ** でよい | **A** | 数分（スペースにアプリを追加するだけ） |
| 新しいスペースで使いたい。保存先は **別のフォルダ** にしたい | **B** | 30分程度（ボットをもう1つ作る） |

> ⚠️ 1つのボットに設定できる保存先フォルダは1つです（`src/Code.js` の `FOLDER_ID`）。
> スペースごとに保存先を分けたい場合はパターンBで、ボットを別に作ってください。

## 2. パターンA：今のボットを別のスペースにも追加する

コードや GCP の設定変更は不要です。

1. Google Chat で導入したいスペースを開きます。
2. スペース名をクリック → **「アプリと統合」**（または「アプリを追加」）を開きます。
3. ボット名（例：`請求書保存Bot`）を検索して **追加** します。
   * 検索に出てこない場合は、GCP の Chat API 構成画面で **「公開設定」** に、そのスペースのメンバーが含まれているか確認してください（[5. トラブルシューティング](#5-トラブルシューティング)参照）。
4. 追加すると、ボットから案内メッセージが届きます。
5. 動作確認として、ファイルを添付し、次のように送信します。
   ```text
   @請求書保存Bot //テスト案件
   ```
6. 保存先フォルダに `【テスト案件】ファイル名` が保存され、完了メッセージが返れば完了です。

## 3. パターンB：別の保存先フォルダを持つボットを新しく作る

今のボットとは別に、もう1つボットを作ります。今のボットには影響しません。

### 3-1. 保存先フォルダを用意する

1. Google ドライブ（マイドライブ／共有ドライブどちらでも可）に保存先フォルダを作ります。
2. フォルダを開き、URL の末尾にある **フォルダID** を控えます。
   ```text
   https://drive.google.com/drive/folders/【ここがフォルダID】
   ```
3. 共有ドライブの場合は、ボットを設定する人のアカウントに **「投稿者」以上** の権限があることを確認します。

### 3-2. GCP プロジェクトを用意する

> 💡 既存ボットの GCP プロジェクトは使い回せません。Chat アプリは **1つの GCP プロジェクトにつき1つ** です。

1. [Google Cloud Console](https://console.cloud.google.com/) で **新しいプロジェクト** を作成します（例：`invoice-bot-2`）。
2. 「APIとサービス」>「ライブラリ」で、次の2つを **有効化** します。
   * `Google Chat API`
   * `Google Drive API`
3. 「APIとサービス」>「OAuth 同意画面」を構成します（User Type：**内部**）。
4. ダッシュボードで **プロジェクト番号**（数字のみ）を控えます。

### 3-3. Apps Script プロジェクトを作る

1. [Google Apps Script](https://script.google.com/) で **新しいプロジェクト** を作成し、名前を付けます（例：`【chat Bot】特定ファイルの保存（〇〇スペース用）`）。
2. 左メニューの **プロジェクトの設定（歯車）** を開きます。
   * 「『appsscript.json』マニフェスト ファイルをエディタで表示する」に **チェック**。
   * 「Google Cloud Platform（GCP）プロジェクト」>「プロジェクトを変更」で、3-2 の **プロジェクト番号** を入力。
3. エディタに戻り、GitHub の最新コードを貼り付けます。
   * `appsscript.json` ← リポジトリの [`src/appsscript.json`](../src/appsscript.json) の中身
   * `コード.gs` ← リポジトリの [`src/Code.js`](../src/Code.js) の中身
4. `コード.gs` の2行目を、3-1 のフォルダIDに書き換えます。
   ```js
   const FOLDER_ID = "ここに新しいフォルダID";
   ```
5. 保存（💾 または `Ctrl + S`）します。
6. 関数のプルダウンで **`authorizeTest`** を選び、**「実行」** します。
   * 承認画面が出たら、アカウントを選んで **許可** します。
   * 実行ログに「保存先フォルダにアクセスできました: フォルダ名」と出れば OK です。

### 3-4. デプロイする

1. 右上の **「デプロイ」>「新しいデプロイ」** を開きます。
2. 種類の選択（歯車）で **「アドオン」** を選びます。
3. 説明（例：`初回`）を入力して **デプロイ** します。
4. 表示された **デプロイ ID** をコピーして控えます。

### 3-5. Chat アプリとして登録する

1. GCP コンソールで「APIとサービス」>「Google Chat API」>「**構成**」タブを開きます。
2. 次のように入力します。
   | 項目 | 設定内容 |
   | :--- | :--- |
   | アプリ名 | 例：`請求書保存Bot（〇〇用）`。既存ボットと区別できる名前にする |
   | アバターの URL | 任意 |
   | 説明 | 例：`請求書を指定フォルダに保存します` |
   | 機能 | 「1対1のメッセージを受信する」「スペースとグループの会話に参加する」に **チェック** |
   | 接続設定 | 「**Apps Script**」を選び、3-4 の **デプロイ ID** を入力 |
   | 公開設定 | 導入するスペースのメンバー（またはドメイン全体）を指定 |
3. **保存** します。

### 3-6. スペースに追加して動作確認

[2. パターンA](#2-パターンa今のボットを別のスペースにも追加する) の手順2〜6と同じです。新しく作ったボット名で追加してください。

> 📝 新しいボットを作ったら、**フォルダID・GCPプロジェクト名・GASプロジェクト名・デプロイID** をどこかに記録しておくと、更新時に迷いません。

## 4. コードの更新手順

GitHub のコードが更新されたとき、実際に動いているボットに反映する手順です。
**ボットが複数ある場合は、ボットごとにこの手順を行います。**

### 4-1. 最新のコードを確認する

1. GitHub のリポジトリで [`src/Code.js`](../src/Code.js) と [`src/appsscript.json`](../src/appsscript.json) を開きます。
2. 変更内容はコミット履歴（「History」）で確認できます。

### 4-2. GAS エディタにコードを貼り付ける

1. 対象ボットの Apps Script プロジェクトを開きます。
2. **今の `FOLDER_ID` の値を控えておきます**（ボットごとに違うため）。
3. `コード.gs` の中身を全て消し、GitHub の `src/Code.js` の中身を貼り付けます。
4. 2行目の `FOLDER_ID` を、**手順2で控えた値に戻します**。
5. `appsscript.json` に変更があった場合は、そちらも貼り付けます。
6. 保存します。
7. `appsscript.json` のスコープ（`oauthScopes`）が変わった場合は、`authorizeTest` を実行して再承認します。

### 4-3. 新しいバージョンを反映する

**おすすめ：デプロイ ID を変えずに更新する方法**

1. 右上の **「デプロイ」>「デプロイを管理」** を開きます。
2. 使っているデプロイを選び、**鉛筆マーク（編集）** をクリックします。
3. 「バージョン」で **「新バージョン」** を選びます。説明に変更内容（例：`//以降を案件名にする`）を書きます。
4. **デプロイ** をクリックします。

デプロイ ID が変わらないため、GCP の Chat API 構成を変更する必要はありません。

<details>
<summary>「新しいデプロイ」で更新した場合（デプロイ ID が変わる）</summary>

「デプロイ」>「新しいデプロイ」で作り直すと、新しいデプロイ ID が発行されます。この場合は、GCP の「Google Chat API」>「構成」で、**接続設定のデプロイ ID を新しいものに書き換えて保存** してください。
書き換えないと、ボットは古いコードのまま動きます。

</details>

### 4-4. 動作確認

1. ボットが入っているスペースで、ファイルを添付して `@ボット名 //テスト案件` と送信します。
2. 保存先フォルダに保存され、完了メッセージが返ることを確認します。
3. 確認用に保存したファイルは削除して構いません。

## 5. トラブルシューティング

| 症状 | 確認すること |
| :--- | :--- |
| スペースでアプリを検索しても出てこない | GCP の Chat API 構成で「公開設定」に自分（またはスペースのメンバー）が含まれているか |
| 「ボットから応答がありません」と出る | ① `authorizeTest` を実行して承認したか ② Google Drive API を有効化したか ③ Chat API 構成のデプロイ ID が正しいか |
| 「プロジェクト名が見つかりません」と返ってくる | テキストに `//案件名` が入っているか（全角の `／／` も可） |
| 更新したのに古い動きのまま | 4-3 で「新バージョン」を選んでデプロイしたか。新しいデプロイを作った場合は、Chat API 構成のデプロイ ID を書き換えたか |
| 共有ドライブに保存できない | ボットを設定した人のアカウントに、共有ドライブの「投稿者」以上の権限があるか |
| `authorizeTest` で「フォルダが見つかりません」系のエラー | `FOLDER_ID` が正しいか、そのフォルダにアクセス権があるか |
| `@個人名` を付けずに送ったら反応しない | スペースでは **ボットへのメンション** が必須です（`@ボット名 ... //案件名`） |
